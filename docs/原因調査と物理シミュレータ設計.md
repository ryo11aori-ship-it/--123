# 原因調査と物理シミュレータ設計

対象: 旧実装 (`cannon-es` + 自前ガード処理) の「サイコロがお椀を貫通する」「最初からお椀の外に出ている」問題と、その解決として作った自作の物理シミュレータ。

---

## 1. 原因調査 (旧コードの `src/game/threeScene.ts`)

旧コードを読んで、数値で裏取りできたものを **確定**、コードの読みからの推論を **推論** として分けて書きます。
(旧コードは実行環境に `cannon-es` が無く動かせなかったため、物理エンジン内部の挙動そのものの再現はしていません。)

### 症状A: サイコロがお椀を貫通して見える

| # | 原因 | 根拠 | 区分 |
|---|---|---|---|
| A1 | **見た目のお椀と当たり判定の形が別物** | 見た目は円錐 (半径 6.7→9.1, `L177`)。当たり判定は「半径9.5の四角い平らな床 (`L254`)」+「箱36枚の壁 (`L273`)」。床の高さ y=0.7 で、見た目の壁は r=6.99、物理の壁は r=8.82 → **差 +1.83 (サイコロ約1.7個分)**。この帯の中をサイコロは「見えない床」の上で転がり、見た目では壁にめり込む | 確定 (幾何を数値計算) |
| A2 | **壁の傾きが逆向き** | コメントは「内側へ傾斜させてすり鉢状に」だが、`Math.PI*0.04` を z 軸まわりに掛けると壁の上端が内側へ倒れる (`L284-288`)。内側の面は下端 r=8.90 → 上端 r=8.12 のオーバーハング。縁の高さ y=4.4 では物理の壁(8.35)が見た目の縁(9.10)より 0.75 内側にあり、空中の壁に当たって跳ね返る | 確定 (数値計算) |
| A3 | **座標を直接書き換えるガード処理** | 毎フレーム、`position.y` を床の高さへ強制 (`L637-638`)、半径が大きいと座標を引き戻す (`L646-652`)。接触ソルバの状態と矛盾するため、跳ね方がおかしくなり、貫通を隠すだけで直していない | 確定 (コード) |
| A4 | **連続衝突判定なし + フレームレート依存** | `world.step(1/60, 1/60, 3)` (`L622`) は表示のフレームレートに関係なく1フレーム=1ステップ進める。144Hz のモニターでは 2.4 倍速になる。サイコロ同士の衝突は最大で1ステップに賽1個分近く進み、すり抜け得る | 確定 (コード) / すり抜けは推論 |
| A5 | **4.2秒で強制スリープ** | 動いていても `body.sleep()` (`L496,504,512`) → 空中や傾いた姿勢で固まる。しかも傾いた賽・重なった賽の判定がなく、そのまま目を読む | 確定 (コード) |

### 症状B: 最初からお椀の外に出ている

| # | 原因 | 根拠 | 区分 |
|---|---|---|---|
| B1 | **初期位置が机の下で、5個とも同一座標** | `createDice` が 5個すべてを `position.set(0, -20, 0)` に置く (`L422`)。机の面は y=0、床の箱は -3.3〜0.7 なので **固体の内部** に重なって生成される | 確定 (コード) |
| B2 | 起動直後に起きること | 最初のステップで強烈な押し出しが発生し、ガード (A3) が y を無理やり床へ戻す → 重なった5個が接触解決で弾き飛ばされる | 推論 (動作未再現) |
| B3 | **ションベンは「演出」で物理ではない** | 1% の抽選 (`L439`) に当たると、0番の賽だけを高さ8・横速度14で投げ出し、ガード対象から外す (`L447, L633`)。お椀の縁を物理的に越えているのではなく、壁より高い所から放っているだけ | 確定 (コード) |

結論: **原因の中心は「見た目と物理の形状が別々に手作業で作られていて、一致していなかったこと」と、それを後から座標の書き換えで隠そうとしたこと**。
ガード処理を足すのではなく、構造そのものを変える必要がありました。

## 2. 新しい物理シミュレータの設計

### 2.1 見た目と当たり判定を同じデータから作る
お椀は **断面の母線 (`bowlProfile.ts`) + 凹凸マップ (`bowlBump.ts`)** だけが唯一のソースです。

- 描画メッシュ: この母線を回転して作り、凹凸を頂点の高さと法線に反映
- 当たり判定: 同じ母線から断面の符号付き距離場(SDF)を焼き込み、凹凸を `φ' = φ − b·n_y` として重ねる

`npm run verify:mesh` で「見えている内面の頂点が SDF の 0 等値面にあるか」を検査しており、結果は **最大 0.7µm のずれ** (法線の一致 cos=1.0000)。旧実装の A1/A2 を構造的に起こさない設計です。

実寸ベースの寸法 (SI単位): サイコロ 16mm角・角丸R1.5mm・4.6g / お椀 内径約16cm・高さ約6.7cm・底は曲率半径50mmのなだらかな曲面 / 重力 9.81m/s²。

### 2.2 物理エンジン (`world.ts`)
Box2D v3 の "Soft Step" に近い逐次インパルス法を、5個の角丸サイコロ向けに3D化。

- **投機的接触**: 1ステップで届く距離内の隙間も拘束にするので、すり抜けない (A4 への対策)
- 固定刻み (既定 480Hz)。表示のフレームレートとは無関係 → どの画面でも同じ動き
- ウォームスタート、ソフト接触、緩和パス、反発は最後に反復適用 (多点接触でも収束)
- クーロン摩擦 (接線2方向を円錐で制限)。立方体は慣性が等方なのでジャイロ項なし
- サイコロ×お椀/机: 内箱表面のサンプル点(各点に半径ρの球)と SDF
- サイコロ×サイコロ: 内箱どうしの最短距離 (頂点-面 / 辺-辺) − 2ρ
- 材質: 釉薬(摩擦0.27・反発0.62)、金縁、外側、机(0.42・0.42)、サイコロ同士(0.30・0.58)
- 静止判定は「接触しているうえで 0.35秒 ほぼ動かない」。強制スリープなし

基礎物理の単体検証 (教科書値との比較):

| 実験 | 理論 | 実測 |
|---|---|---|
| 机の上を滑る (v₀=1m/s, μ=0.42) | 12.14 cm | 12.00 cm |
| サイコロ同士の正面衝突 (e=0.5, ±0.5m/s) | ∓0.250 m/s | ∓0.2500 m/s、余計な回転 0.004 rad/s |
| 斜め衝突3種 | 力学的エネルギーは増えない | 1ステップたりとも増加なし |

### 2.3 投擲と判定 (`throw.ts`, `rollJob.ts`)
- 投げ方: 椀の真上から落とす / **縁の上から放物線で放り込み、向こう岸の壁に当ててカラカラ回す** (実際のチンチロの投げ方) を混ぜる。位置・高さ・狙い・強さ・各賽の向きと回転が乱数
- **先に最後までシミュレーションして記録 → 再生**。結果が事前に確定し、演出中に止まる/ズレることがなく、スロー再生やカメラ演出が自由
- 時間分割で計算するので、持ち上げて振る演出の裏で UI を止めずに進む
- 判定:
  - 椀外へ出た賽 → ションベン
  - **傾き** (底面が椀の面から 15° 超) / **賽の上に賽が乗っている** → ノーカウントとして、別の初期条件で自動的に振り直し (遊び手には見えない)
  - 静止した賽の傾きは 5°未満が 99.5% で、5〜30° にはほぼ存在しない (閾値の根拠)

### 2.4 「物理シミュレーション乱数」としての仕組み
目は乱数で決めず、**物理シミュレーションの結果として読み取ります**。乱数が使われるのは初期条件だけです。

- 乱数源: `crypto.getRandomValues` + 操作のタイミング/ポインタのゆらぎ → 128bit シード → sfc32
- お椀の凹凸: ろくろ目(同心円) + うねり + 槌目(約300個のくぼみ) + ピンホール/釉だまり16個。RMS 0.15mm・最大 0.7mm
- 賽の角は R1.5mm なので、数mm の凹凸に当たるたびに弾道が変わり、結果が複雑に変わる (カオス的な感度)

### 2.5 ションベン (仕様: 1投擲あたり固定1%)
仕様は変えていません。1% の抽選に当たったときだけ、**椀外へ飛び出す投擲を物理シミュレーションで探索**します。
「放り上げて縁を越える」「叩きつけて跳ね上げて縁を越える」の2通りの投げ方で、成功率は約43%/試行 (平均2.3試行、中央値74ms)。
抽選以外では椀外へ出た場合は **見えないところで振り直し** ます (自然な脱出は 5.8%/試行。表示される結果の 99% は椀内、ションベンはちょうど 1%)。

## 3. 検証結果 (`npm run verify:physics`、最終コードでの実測)

全文は [`verify-physics-output.txt`](verify-physics-output.txt)。

| 項目 | 結果 |
|---|---|
| 公平性 (1,000投擲×5個) | χ²=5.59 (5自由度, p=0.35)。サイコロ5個それぞれも p>0.3 |
| 公平性 (別のお椀で 4,000投擲×5個, 開発中の追加検証) | χ²=10.43 / 1.84 (5%点 11.07) |
| 貫通 (250投擲, 29,544フレーム, 147,720姿勢を全数検査) | 最大めり込み **0.376mm**、1mm超は **0件**。賽の中心が固体に入ったことは一度もなし |
| 賽どうしのめり込み | 最大 0.012mm |
| 再現性 | 同じシードで 20/20 件が全フレームでビット一致 |
| 凹凸の影響 | 凹凸 ×1 と ×0 で同じ目になった賽は 18.8% (偶然の期待値 16.7%) → 凹凸が結果をほぼ完全に入れ替える |
| 初期条件への感度 | 初期位置を 1µm ずらすと同じ目は 74%、10µm で 51%、0.1mm で 34%、1mm で 24% (開発中の測定) |
| 速度 | 1投擲の計算 中央値 47ms / 90% 73ms / 99% 134ms (Node, 1コア) |
| ションベン生成 | 150/150 件成功、停止位置は椀から 38cm 以内 |

## 4. 既知の制限・未検証のこと (正直に)

- **three.js の実機描画は未確認です。** 作業環境に `three` / `vite` / ブラウザ用 GPU が無かったため、
  - メッシュは Node で数値検証 (面の向き・SDF一致)、テクスチャはブラウザで目視確認
  - シーンマネージャは three.js を差し替えたモックで通し実行 (起動→6回投擲→二重投擲拒否→設定変更→破棄、および WebGL 非対応時の物理のみ動作)
  - **ライトの強さ・影のバイアス・色味の見た目の調整は実機で未確認** です。暗い/明るい場合は右端の歯車 → 「画面の明るさ」で調整してください。
- UI の洗練は限定的です (歯車パネル、ビネット、キーボード操作、動作設定の尊重、`animate-in` の実体化、モーダル表示中の CPU 自動投擲の停止)。既存コンポーネントのデザインは大きく作り替えていません。
- 描画品質(影・メッシュ密度)の変更は再読み込みで反映されます。物理側は次の投擲から反映されます。
- 自然な脱出(5.8%/試行)を棄却して振り直しているため、厳密には「椀内に収まる投擲」で条件付けた分布です。ションベンの 1% は仕様どおり別枠の抽選です。
- 反発係数などの材質値は、実物の丼と賽を想定した **推定値** です。実測で調整できます (`src/physics/constants.ts`)。

### ルールに関する気づき (**変更していません**)
サドンデスの順位付けで、**3人以上が同点でサドンデスに入り、その中で一部だけが再び同点になった場合**、最初のラウンドで負けた人に `sdFinalRankOffset` が付かず、`finalizeGame` の比較でメインゲームの副点にフォールバックします。そのため最終順位が意図とずれる可能性があります。
「ルールは仕様なのでそのまま」とのご指示なので手を入れていません。直す場合は `resolveSuddenDeath` の対象外になった人にも順位オフセットを割り当てる修正になります。
